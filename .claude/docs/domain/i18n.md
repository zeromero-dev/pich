# Locale (i18n)

Cross-cutting concern, not a bounded context — documented because its rules constrain every other context.

## The core rule: UI is bilingual, content is not

Two different kinds of text, two different policies:

1. **UI strings** (labels, buttons, empty states, validation messages) — exist in both locales, in the dictionaries in `lib/i18n.ts`. Ukrainian is the default and the reference shape.
2. **Content** (work names/descriptions from the CRM, event text from Google Calendar, artist bios from the repo) — single-language, displayed as-is under any locale. We do not promise translated content; don't build partial content translation without a decision.

## Model (from the code — `lib/i18n.ts`, `components/providers.tsx`)

- `Locale = 'uk' | 'en'`, default `uk`.
- `Dictionary` is derived structurally from the `uk` dictionary (`DeepString<...>`) — **the uk shape is the contract**. Adding a key means adding it to both locales; a key missing from `en` is a type error at the point where dictionaries are used.
- Locale is client state: persisted in `localStorage["plai-pich-locale"]`, switch updates `<html lang>` at runtime. SSR always renders `uk` first; an `en` user sees their language after hydration.

## Consequence of client-side locale (accepted for v1)

There are **no locale-segment URLs** (`/en/shop`) — one URL serves both languages, so search engines only ever index the Ukrainian UI, and a shared link doesn't carry the language. Accepted because the audience is local and content (the bulk of every page) is single-language anyway. If EN SEO ever matters, the migration is to App Router locale segments — a routing change touching every page; the note in CLAUDE.md's architecture section reflects this.

## Formatting rules (from the code — `lib/format.ts`)

- **Money**: `₴` prefix, non-breaking-space thousands separator, no decimals — "₴12 400". Tabular numerals wherever prices appear.
- **Dates**: locale-aware — "14 серпня, 18:00" (uk, genitive month) / "14 Aug, 18:00" (en). Month grouping labels in nominative ("Серпень" / "August").
- These functions are the only place date/price formatting lives — never inline-format in a component.
